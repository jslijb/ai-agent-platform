## 二、50K+ JD 的 8 大共性特征

### 特征1：从"用框架"到"设计框架"（架构能力）

| 30K-50K 段 | 50K+ 段 |
|------------|---------|
| "熟悉 LangChain/LlamaIndex" | "设计 Agent 编排架构，解决多步推理/工具编排/状态管理" |
| "能写 RAG" | "设计混合检索+rerank+重排策略，解决召回率/精度/延迟三角" |

**关键词**：架构设计 / 从 0 到 1 / 技术选型决策 / ADR 决策记录
**出现频率**：约 85% 的 50K+ JD

### 特征2：评估与优化闭环（不只是"能跑"）

| 普通要求 | 50K+ 要求 |
|---------|----------|
| "能评估 RAG 效果" | "建立评估体系（指标设计+数据集+自动化），持续优化闭环" |
| - | "RAGAS/DeepEval/LangSmith 评估" / "A/B 测试框架" / "离线+在线评估" |

**关键词**：评估闭环 / 指标体系 / 退化检测 / 数据飞轮
**出现频率**：约 75%

### 特征3：Multi-Agent 与编排（不只是单 Agent）

| 普通要求 | 50K+ 要求 |
|---------|----------|
| "能做 Agent" | "Multi-Agent 协作/角色分工/A2A 通信/任务分解" |
| - | "LangGraph/AutoGen/CrewAI 编排" / "Agent 间消息协议" |

**关键词**：Multi-Agent / 角色协作 / 任务分解 / A2A
**出现频率**：约 70%

### 特征4：工程化与高可用（生产级）

| 普通要求 | 50K+ 要求 |
|---------|----------|
| "能部署" | "高并发/限流/熔断/降级/灰度/可观测/成本治理" |
| - | "K8s/微服务/分布式" / "Prometheus/Grafana" / "SLA 保障" |

**关键词**：高可用 / 限流熔断 / 可观测 / 成本治理 / SLA
**出现频率**：约 80%

### 特征5：垂直领域深度（不是通用 chatbot）

| 通用 Agent | 50K+ 垂直 |
|-----------|----------|
| 做通用问答 | 金融/医疗/法律/电商等垂直，懂领域知识+合规+数据治理 |

**关键词**：领域知识 / 合规风控 / 数据治理 / 行业模型
**出现频率**：约 65%（50K+ 中金融/医疗/法律方向）

### 特征6：模型层深度（不只调 API）

| 普通要求 | 50K+ 要求 |
|---------|----------|
| "调 OpenAI API" | "模型微调（LoRA/QLoRA）/RLHF/DPO/推理优化（vLLM/量化）" |
| - | "私有化部署" / "模型选型+降级链" / "成本优化" |

**关键词**：微调 / RLHF / vLLM / 量化 / 私有化
**出现频率**：约 55%

### 特征7：数据飞轮与知识工程

| 普通要求 | 50K+ 要求 |
|---------|----------|
| "建知识库" | "数据飞轮：badcase→标注→训练→评估→上线" / "知识图谱" / "数据治理" |

**关键词**：数据飞轮 / 知识图谱 / badcase 闭环 / 数据治理
**出现频率**：约 60%

### 特征8：Action Agent（能执行动作，不只问答）

| 2024 年前 | 2025-2026 50K+ |
|----------|---------------|
| 做问答 | "Agent 能调外部系统/提交流程/操作工具/RPA 融合" |

**关键词**：Function Calling / Tool Use / RPA / 系统集成 / Action Agent
**出现频率**：约 50%（2026 年新出现的强趋势）

## 五、不能融入本项目的特征（需另立项目）

### 5.1 模型训练/微调（LoRA/QLoRA/RLHF/DPO）

| 为什么不能融入 | 理由 |
|--------------|------|
| 硬件 | 本地 i7/16GB 无 GPU，微调需 A100/H100 |
| 定位 | 项目是"应用层"，不是"模型层" |
| 成本 | 微调需标注数据 + 训练集群 + 评估，周期长 |

**建议另立项目**：**AI FinModel Lab**（金融大模型微调实验室）
- 定位：金融垂直模型微调 + 评估 + 部署
- 输入：本项目 badcase + 金融数据
- 输出：微调模型 → 反哺本项目降级链
- 关系：与本项目互补，本项目是"应用"，FinModel Lab 是"模型工厂"

### 5.2 通用 Agent 平台（不限垂直）

| 为什么不能融入 | 理由 |
|--------------|------|
| 定位冲突 | 项目是金融垂直，通用平台会稀释专业度 |
| 竞争 | 通用 Agent 平台（Dify/Coze/FastGPT）已红海 |

**不建议另立**：通用平台是红海，垂直才有壁垒。

### 5.3 AI Infra（推理框架/vLLM/TGI）

| 为什么不能融入 | 理由 |
|--------------|------|
| 定位 | 项目是应用层，不是基础设施 |
| 复用 | 直接用开源 vLLM 即可，不必自研 |

**建议**：不自研，**直接用 vLLM** 做私有化推理（对应 R026）。

## 六、结论

### 6.1 50K+ JD 的核心信号

**能拿 50K+ 的 AI Agent 工程师，不是"会用框架"，而是"能设计系统 + 评估闭环 + 落地业务 + 优化模型"**。本项目已具备其中 3 项（架构/垂直/部分评估），V3.0 补齐另外 4 项（Action Agent/评估闭环/模型层/数据飞轮）后，可作为 50K+ 岗位的**作品级证明**。

### 6.2 对本项目的启示

| 启示 | 动作 |
|------|------|
| Action Agent 是 2026 分水岭 | V3.0 必须做 OA/CRM 接入 |
| 评估闭环是 50K+ 标配 | V3.0 必须补 Agent 评估 + A/B |
| 模型层深度拉开差距 | V3.0 纳入 Hermes-3 + vLLM 私有化 |
| 数据飞轮是长期壁垒 | V3.0 建 badcase 自动闭环 |

### 6.3 另立项目建议

| 项目 | 定位 | 与本项目关系 |
|------|------|-------------|
| **AI FinModel Lab** | 金融模型微调实验室 | 互补（模型工厂→反哺应用） |
