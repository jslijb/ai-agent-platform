# AI Agent Platform 优化迭代规划

> 基于项目当前实际存在的问题，分近期/中期/远期三个阶段给出具体优化点。所有问题均来自前期开发中真实发现，非凭空设想。

## 近期优化（1-2 周）：修复止血，评估达标

**目标**：完成 V11 评估，6 项核心指标全部达到优秀线，系统可进入试点。

### 1. 完成 metadata 索引重建（A5）— 优先级 P0

```
当前状态：代码已修复（upload/route.ts、incremental-embedder.ts、rebuild-index/route.ts 三处）
待执行：重建 5160 条 embedding 的索引，补上 source/startPage/endPage
预期收益：前端召回片段展示来源、PDF 跳转高亮恢复正常
```

### 2. 运行 V11 全量评估并达标（A1-A4 + B6）— 优先级 P0

```
当前状态：Task 1-10 完成，Task 11 待执行
待执行：npx tsx scripts/run-evaluation.ts --type rag --level full
验收标准：6 项指标全部 ≥ 优秀线（Hits@K≥0.85, AnswerRelevance≥0.80, Faithfulness≥0.85）
若不达标：逐条分析"需人工核查"列表，定位是数据问题还是检索问题
```

### 3. 修复 orchestrator timeout 不一致（B4）— 优先级 P1

```
问题：orchestrator.ts 第27行 AGENT_TIMEOUT_MS=120000，README 记载 240000
修复：统一为 240000，与 simpleAgent.ts 的 AGENT_TIMEOUT_MS=300000 对齐
注意：orchestrator 用于多 Agent 编排，timeout 应 ≥ SimpleAgent 单次执行
```

### 4. compliance_logs 迁移正规化（B5）— 优先级 P1

```
问题：表通过 docker exec psql 手动创建，不在迁移流程内
修复：生成 drizzle migration 文件，纳入版本管理
方法：drizzle-kit generate（非 push，避免 TTY 问题）→ docker exec 执行 SQL
```

### 5. 评估"需人工核查"闭环（B7）— 优先级 P1

```
问题：评估报告输出"需人工核查"列表，但核查结果无回流入口
修复：新增 /api/wrong-answers 接口对接，核查发现的错误自动写入错题本
闭环：评估→人工核查→错题本→修正测试集/知识库→下一轮评估
```

### 6. L4 趋势分析专项优化（B1）— 优先级 P1

```
问题：L4 AnswerRelevance 0.38（最低），知识库缺同比/环比数据
方案：
  - 检查知识库文档是否含"本年比上年增减"列（财报标准格式）
  - 若切片丢失表格数据，调整 chunkDocument 的表格识别策略
  - 在 QueryExpander 增加"同比增长/环比/同比"同义词扩展
验收：L4 AnswerRelevance ≥ 0.75
```

## 中期优化（1-2 月）：工程化提升，规模验证

**目标**：系统具备生产级稳定性，可支撑多客户试点，评估指标稳定在优秀线。

### 1. 文档入库质量校验（C4）— 优先级 P0

```
问题：PDF 解析失败静默处理，脏数据入库影响检索
方案：
  - 入库后自动校验：chunkText 非空、tokenCount > 0、embedding 非 zero 向量
  - 校验失败标记 status="parse_failed"，不进入检索索引
  - 新增 /api/document/quality-report 接口，输出文档质量报告
  - 前端文档管理页增加质量标识（绿/黄/红）
```

### 2. 合规防护第 5-6 层（C2）— 优先级 P0

```
当前：第 1-4 层已实现（拒绝+日志+分级+阈值审核）
补充：
  - 第 5 层 监管上报：Unsafe 级事件按月汇总，生成合规报告（PDF），供向主管部门报送
  - 第 6 层 AML/KYC 联动：高风险用户（24h 内 ≥5 次 Unsafe）触发 KYC 重新认证
监管依据：《生成式AI办法》第十五条"向有关主管部门报告"
```

### 3. A/B 测试框架（C3）— 优先级 P1

```
问题：改进效果无法对比验证（V1-V11 只能纵向比，无法同期对比）
方案：
  - 新增 ab_test 表：experimentId/variant/query/result/metrics
  - 流量按 userId hash 分桶（50/50）
  - 评估脚本支持 --ab-test 参数，输出 A/B 组指标对比
  - 前端评估页新增 A/B 实验看板
应用场景：chunk size 800 vs 1200、有无 HyDE、不同 rerank topK
```

### 4. 多 Agent 编排补全（B2 + B3）— 优先级 P1

```
问题：compliance.ts 和 a2a/protocol.ts 为空文件
方案：
  - compliance Agent：封装合规检查技能，独立处理 L7 类问题
  - A2A 协议：实现 Agent 间通信，支撑"综合诊断"等嵌套场景的分布式执行
注意：优先级低于合规和数据质量，属架构完善
```

### 5. LLM 成本治理（C5）— 优先级 P1

```
问题：LLM 调用无预算告警，生产环境成本失控
方案：
  - 复用已有 LLMUsageLog 表，新增 /api/llm-usage/budget 接口
  - 按用户/模型/调用类型设置日预算阈值
  - 超阈值 80% 告警，100% 降级（切换低成本模型或拒绝非核心请求）
  - 前端 Token 用量页增加预算仪表盘
```

### 6. 开源数据集评估常态化（B6 持续提升）

```
当前：4 个开源数据集已接入（FinEval/CFLUE/FinQA/ConvFinQA），但未定期跑
方案：
  - CI/CD 增加 weekly job：每周一自动跑 4 个数据集评估
  - 指标退化 >5% 自动告警，阻塞部署
  - 评估结果写入 evaluation_versions 表，支持趋势查看
目标：FinEval ≥80%、CFLUE ≥83%、FinQA ≥75%、ConvFinQA ≥72%
```

### 7. 检索链路全链路追踪

```
问题：检索质量问题时，定位是 dense/sparse/rerank/graph 哪一环困难
方案：
  - 每次检索记录全链路 trace（denseRecall/sparseRecall/graphRecall/beforeRerank/afterRerank）
  - 写入 AgentLog.steps 的 retrieval 节点
  - 前端召回片段展示时，显示每环召回数和耗时
  - 新增 /api/rag/trace/:queryId 接口
```

## 远期优化（3-6 月）：规模化复制，场景扩展

**目标**：平台可规模化复制到多个金融机构，支撑新业务场景。

### 1. 多租户隔离（C1）— 优先级 P0

```
问题：当前单用户测试，无租户隔离
方案：
  - DB 层：所有业务表新增 tenantId 字段，RLS（Row Level Security）策略
  - 应用层：API 中间件注入 tenantId，所有查询自动过滤
  - 知识库：按租户隔离 Document/Embedding，支持租户级独立知识库 + 共享知识库
  - 合规日志：按租户隔离，支持租户级合规报告导出
应用场景：券商 A 和券商 B 数据完全隔离，但共用平台基础设施
```

### 2. 管理后台（合规/运营）

```
问题：合规日志、文档质量、评估配置均通过 SQL 或 API 操作，无 GUI
方案：
  - 合规中心：合规日志查询/导出/告警配置/人工审核工单
  - 运营中心：文档质量管理/评估配置/用户管理/租户管理
  - 成本中心：LLM 用量/预算/告警/A/B 实验看板
技术：复用现有 dashboard 布局，新增 /admin/* 路由
```

### 3. 新业务场景扩展

| 场景 | 复用能力 | 新增能力 |
|:---|:---|:---|
| 信贷审批 | RAG + 合规日志 + 文档解析 | 信贷规则引擎、征信数据接入 |
| 保险理赔 | RAG + 文档 OCR + 多模态 | 理赔单据识别、定损规则 |
| 反洗钱 | 合规日志 + 意图识别 + 图谱 | 交易图谱分析、可疑模式检测 |
| 投资者教育 | RAG + 对话 | 教育内容库、学习路径推荐 |

### 4. 持续改进机制（合规第 7 层）

```
当前：意图识别关键词硬编码，规则更新需发版
方案：
  - 关键词规则外置为配置文件，支持热更新
  - 新增 /api/compliance/rules 接口，管理后台可编辑
  - 合规日志定期分析，自动发现新型违规模式，推荐规则补充
  - 建立"规则版本"概念，支持回滚
```

### 5. 性能优化（支撑规模化）

```
当前：评估 130 条需 1-2 小时，生产并发能力未知
方案：
  - 检索层：pgvector HNSW 索引调优（ef_search 参数）
  - 缓存层：热点 query 语义缓存（已有框架，需调优命中率）
  - 并发层：Agent 执行引入队列（BullMQ 已引入，需配置并发数）
  - 评估层：并行评估（当前串行，改为按 category 并行，预期耗时降 60%）
目标：单 query P95 延迟 < 5 秒，评估 130 条 < 30 分钟
```

### 6. 模型国产化与私有化部署

```
当前：依赖阿里百炼（云端），数据出境合规风险
方案：
  - 接入更多国产模型：通义千问本地部署、智谱 GLM、深度求索 DeepSeek
  - 私有化部署方案：全部模型本地化（BGE-M3 + 本地 LLM），数据不出内网
  - 模型路由策略：合规优先用本地，性能优先用云端，成本优先用小模型
```
