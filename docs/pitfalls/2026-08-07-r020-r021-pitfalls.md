# 踩坑记录：R020+R021 开发

> 日期：2026-08-07

## 踩坑1：drizzle-orm HNSW 索引定义导致运行时崩溃

**现象**：`npx tsx scripts/rebuild-graph.ts --stats` 报错 `SyntaxError: "undefined" is not valid JSON`，定位到 `schema.ts:815` 行的 `index().using("hnsw", ...)` 调用。

**根因**：drizzle-orm 的 `index().using()` API 不支持 `("hnsw", column, { opclass: "vector_cosine_ops" })` 这种参数格式。tsc 类型检查通过但运行时崩溃。

**修复**：移除 schema.ts 中的 HNSW 索引定义（改用原生 SQL 迁移脚本创建），只保留普通索引。

**教训**：
- **tsc 通过 ≠ 运行时正确**，drizzle-orm 的 index API 有运行时参数验证
- HNSW/特殊索引应通过 SQL 迁移脚本创建，不要通过 drizzle schema

## 踩坑2：agnes-2.5-flash 偶发返回空内容

**现象**：LLM 调用成功（tokens=5144），但 `content` 为空字符串（长度0），不触发 agnes provider 的空响应重试（只检查 `content === null`）。

**根因**：agnes API 的 prompt cache 机制偶发返回空字符串而非 null。

**修复**：
1. agnes provider：`content === null` 改为 `content === null || content.length === 0`
2. entity-extractor-v2：空响应时重试一次

## 踩坑3：公司名分类依赖别名表加载

**现象**：`classifyEntity("宜宾五粮液股份有限公司")` 返回 `Entity` 而非 `Company`。

**根因**：`isCompany()` 只检查 `companyAliasMap.has()`，但别名表需要先通过 `loadCompanyAliases()` 加载。

**修复**：
1. 增加 `COMPANY_SUFFIXES` 后缀匹配（不依赖别名表也能识别"xxx股份有限公司"）
2. rebuild-graph.ts 启动时从 stock_mapping 表加载公司别名
3. graph-retriever.ts 启动时也加载公司别名

## 踩坑4：Redis 懒连接导致断点续传进度丢失

**现象**：`--resume` 模式下已处理的文档不被跳过，Redis 中没有进度记录。

**根因**：Redis 客户端是懒连接的，`isRedisConnected()` 在 `getRedis()` 之前返回 false。

**修复**：在 rebuild-graph.ts 的 main() 中主动调用 `await getRedis()` 初始化连接。

## 踩坑5：isAmount 不匹配 "832亿元" 格式

**现象**：数值 "832亿元" 没有被识别为 Amount 类型，导致数值作为独立节点而非关系 value。

**根因**：`AMOUNT_PATTERN` 要求有小数点，`/^[\-−]?[0-9,]+$/` 不匹配带单位的整数。

**修复**：增加 `AMOUNT_INT_PATTERN = /^[\-−]?[0-9,]+(元|万元|亿元|万亿)$/`。

## 踩坑6：mapRelationType 映射不全

**现象**：LLM 返回的关系词不在映射表中，导致所有关系类型为 RELATED_TO。

**修复**：
1. 扩展映射表（增加营收/归母净利润/扣非净利润/控股/参股等）
2. 增加英文 V2 关系类型直通（HAS_REVENUE→HAS_REVENUE）
3. 增加部分匹配（`relation.includes(key)`）
