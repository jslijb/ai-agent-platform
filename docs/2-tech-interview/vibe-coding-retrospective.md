# Vibe Coding 复盘：AI驱动开发的得与失

> 基于 ai-agent-platform 项目75天开发历程的方法论反思
> 最后更新：2026-08-08

---

## 一、什么是 Vibe Coding

Vibe Coding 是一种以AI编程助手为核心驱动力的开发模式——开发者通过自然语言描述需求，AI生成代码，人类负责方向把控、架构决策和质量审核。与传统"手写代码"不同，Vibe Coding 的核心循环是：

```
意图描述 → AI生成代码 → 人类审查/修正 → 运行验证 → 迭代优化
```

本项目从2026-05-25到2026-08-07，75天内完成了从零到生产级AI Agent平台的全部开发，包括：
- 全栈应用（Next.js + FastAPI + PostgreSQL + Neo4j + Redis）
- 5个Docker容器编排 + nginx统一入口
- 18项核心技术（ReAct循环/知识图谱/语义缓存/反思检测等）
- 评估基线从0.60提升到0.92
- 564个单元测试 + 5/5 E2E测试通过

**这一切，几乎100%由AI生成代码。**

## 二、做得好的地方（8项）

### 2.1 极速原型 → 生产级交付

| 指标 | 数据 |
|------|------|
| 首日提交 | 2026-05-25 first commit |
| 单日最高 | 2026-06-01 25个commit（SimpleAgent+Skill+Tool+OCR+评估全栈） |
| 评估迭代 | 2天内8个版本（V1-V8），1周内14个版本 |
| 总开发天数 | ~30天活跃开发 |

**Vibe Coding优势**：AI可以同时生成前端组件、后端API、数据库Schema、测试用例，人类只需审查和拼接。传统开发需要数周的全栈功能，AI一天就能生成初版。

**关键经验**：Vibe Coding的效率优势在**从0到1阶段**最为显著。一旦进入精细调优阶段（评估从0.60→0.92），效率优势会递减，但仍然远超手写。

### 2.2 文档即记忆：CLAUDE.md 机制

这是本项目最重要的Vibe Coding创新——**用文档解决AI会话上下文丢失问题**。

```
CLAUDE.md（开机自检清单）
├── 快速恢复：项目当前状态（架构/容器/基线/硬件）
├── 用户反复强调的需求（4条不可遗忘）
├── 文档索引（3类目录导航表）
├── 关键踩坑速查（8条必须记住的结论）
└── 当前任务清单（已完成/待办）
```

**为什么有效**：
- AI每次新会话自动读取CLAUDE.md，5分钟恢复全局认知
- 踩坑结论以"速查表"形式存在，避免重复犯错
- 用户反复强调的需求被显式记录，AI不会反复询问

**对比传统开发**：传统开发靠人的记忆和README，Vibe Coding靠结构化文档+AI自动读取。后者更可靠，因为AI不会忘记文档内容。

### 2.3 踩坑即规范：从Bug到检查清单

每个Bug修复后，提炼为可执行的检查清单：

| Bug | 提炼的规范 |
|-----|-----------|
| AUTH_SECRET不一致→JWT 401 | "三处环境变量必须一致" |
| Docker构建阶段DB不可达 | "build阶段用host.docker.internal" |
| 评估ground_truth循环依赖 | "评估前校验ground_truth来源" |
| drizzle HNSW索引运行时崩溃 | "特殊索引通过SQL迁移创建" |
| agnes空响应不检测 | "content.length===0也触发重试" |

**Vibe Coding优势**：AI会在不同会话中重复犯同样的错误（因为上下文被压缩）。踩坑记录+检查清单是唯一有效的防复发机制。

### 2.4 SDD流程与Vibe Coding的融合

Spec-Driven Development（规格驱动开发）三层文档体系：

```
spec.md（WHAT）→ design.md（HOW）→ task.md（WHEN）
     ↓                ↓                ↓
   需求约束          技术方案          任务分解
```

**为什么Vibe Coding需要SDD**：
- AI没有全局视野，必须通过spec约束其行为边界
- 没有spec，AI会"自由发挥"——生成看似合理但偏离需求的代码
- spec→design→task的级联机制，确保AI每次只关注当前task，不被全局复杂性淹没

**实际效果**：R016-R021共6个需求，每个都有明确的约束和验收标准，AI按task执行，零偏差。

### 2.5 评估驱动的快速迭代

```
V1(0.60) → V2 → V3 → V4 → V5 → V6 → V7 → V8
    → V11(RAGAS) → V12(0.57) → V13-r2(0.82) → V13-r6(0.92)
```

**Vibe Coding优势**：
- AI可以快速调整prompt/权重/策略，人类只需评估结果
- 评估→发现问题→AI修复→再评估，循环周期从传统开发的"天"缩短到"小时"
- 14个评估版本在2周内完成，传统开发至少需要2个月

### 2.6 复杂架构的AI生成能力

本项目涉及的技术栈复杂度：
- **前端**：Next.js App Router + SSE流式 + Drizzle ORM + NextAuth
- **后端**：FastAPI + PaddleOCR + pdfplumber + efinance + mootdx
- **数据库**：PostgreSQL(pgvector) + Neo4j + Redis
- **AI**：ReAct Agent + Function Calling + 知识图谱 + 语义缓存
- **运维**：Docker 5容器 + nginx + CI/CD

**Vibe Coding优势**：AI可以跨技术栈生成代码——前端组件、后端API、数据库迁移、Docker配置、测试用例，人类只需做架构决策和代码审查。

### 2.7 ADR决策记录：AI时代的架构日志

11份ADR记录了所有重大技术决策的**上下文、选项、对比、结论**。

**为什么Vibe Coding需要ADR**：
- AI在不同会话中可能做出矛盾的架构决策（因为不记得之前的决策）
- ADR是"决策的持久化"，新会话的AI读取ADR后能保持架构一致性
- 面试时ADR是"决策能力"的最佳证据

### 2.8 三类目录的文档体系

```
docs/
├── 1-requirements-bugs/    ← 需求+踩坑+Bug（只追加不修改）
├── 2-tech-interview/       ← 技术讨论+面试准备
└── 3-standards/            ← SDD+TDD规范（spec/design/task）
```

**Vibe Coding优势**：分类清晰的文档体系让AI在不同上下文中快速定位所需信息，减少"大海捞针"式的搜索。

## 三、不足与改进（10项）

### 3.1 ❌ 无Prompt版本管理

**问题**：AI生成的代码质量高度依赖prompt措辞，但我们没有记录"哪个prompt生成了哪段代码"。

**影响**：
- 无法复现"那次效果很好的生成"
- 同样的需求，换个prompt措辞，AI可能生成完全不同的代码
- 调试时无法回溯"当时AI是怎么理解的"

**改进方案**：
- 在git commit message中记录关键prompt片段
- 建立prompt模板库，按场景分类
- 对关键生成（如systemPrompt），记录prompt→输出的映射关系

### 3.2 ❌ tsc通过 ≠ 运行时正确

**典型案例**：
- drizzle-orm HNSW索引：`index().using("hnsw", column, { opclass: "vector_cosine_ops" })` 在tsc中通过但运行时崩溃
- Node.js v24正则变化：`/\d/`在字符类中不匹配数字，tsc无法检测

**根因**：AI生成的代码依赖类型系统的"安全保证"，但类型系统无法覆盖运行时行为。

**改进方案**：
- **强制冒烟测试**：每个新模块必须实际运行验证，不能只靠tsc
- **运行时断言**：关键路径增加`if (!result) throw new Error(...)`，而非仅靠类型推断
- **CI增加运行时测试**：不只是`npm run build`，还要`npm run smoke-test`

### 3.3 ❌ 会话压缩导致的信息丢失

**问题**：AI上下文窗口有限，长会话必须压缩。压缩后：
- 细节决策理由丢失（"为什么选方案A而不是B"）
- 调试过程中的中间结论丢失
- 用户偏好丢失（除非已写入文档）

**实际案例**：历史对话bug修复过程中，AUTH_SECRET不一致的根因在第一次会话中被发现，但压缩后新会话的AI又花了30分钟重新排查。

**改进方案**：
- **关键发现立即写入文档**，不等会话结束
- **CLAUDE.md增加"近期决策"板块**，记录最近3-5个重要决策
- **会话结束前执行"记忆转储"**，将重要信息写入文档

### 3.4 ❌ AI幻觉的隐蔽性

**典型案例**：
- 工具返回`fetch failed`，Agent编造完整的股票数据（规则15"数据真实性原则"的由来）
- 评估ground_truth用向量检索结果生成，再用它评估向量检索质量（循环依赖）
- LLM额度耗尽时，评估脚本静默返回0分而非报错

**Vibe Coding特有风险**：AI生成的代码看起来合理，但可能包含"看起来对但实际错"的逻辑。人类审查时容易被"代码风格正确"误导，忽略逻辑错误。

**改进方案**：
- **关键路径增加断言**：工具返回值必须校验，不能信任AI生成的"happy path"
- **评估系统增加自检**：ground_truth来源校验、LLM可用性预检
- **异常路径显式处理**：每个`catch`块必须有日志+降级策略，不能静默吞掉

### 3.5 ❌ 缺乏Token成本追踪

**问题**：Vibe Coding消耗大量LLM Token，但我们没有追踪：
- 每次会话消耗多少Token
- 哪些操作最耗Token
- Token消耗与代码质量的关系

**影响**：无法优化Vibe Coding的效率——不知道哪些prompt是"高成本低产出"的。

**改进方案**：
- 在AI调用链中增加Token计数器
- 按功能模块统计Token消耗
- 建立"Token效率"指标：代码行数/Token消耗

### 3.6 ❌ 架构漂移风险

**问题**：不同会话的AI可能做出不一致的架构决策。

**实际案例**：
- 早期会话用Prisma，后期切换Drizzle（ADR-001记录了决策，但切换前已生成大量Prisma代码）
- Agent架构从单体→多Agent→6工具合并，经历了3次重大重构
- 缓存从SQLite→PostgreSQL，数据存储从MongoDB→PostgreSQL

**改进方案**：
- **ADR前置**：做架构决策前先写ADR，而非事后补写
- **架构决策门禁**：涉及全局架构的变更，必须先更新design.md再写代码
- **定期架构审计**：每5个需求完成后，审查架构一致性

### 3.7 ❌ 测试覆盖的假象

**问题**：564个单元测试全通过，但仍有运行时bug。

**根因**：
- AI擅长生成"happy path"测试，不擅长生成边界条件和异常路径测试
- Mock隔离了外部依赖，但真实环境中的集成问题无法被单元测试捕获
- E2E测试只覆盖5个query，远不够

**改进方案**：
- **增加异常路径测试**：每个工具至少1个失败case
- **集成测试比重增加**：Mock→真实服务连接
- **E2E测试扩展**：从5个→20个query，覆盖更多边界场景
- **属性测试（Property-based Testing）**：用随机输入验证不变量

### 3.8 ❌ 缺乏代码质量门禁

**问题**：AI生成的代码没有统一的质量标准。

**实际案例**：
- 硬编码：API密钥、端口号、模型名散落在代码中
- 魔数：`maxIterations: 5`、`threshold: 0.95`等没有命名常量
- 重复代码：多个模块有相似的错误处理逻辑

**改进方案**：
- **ESLint + 自定义规则**：禁止硬编码、强制命名常量
- **代码审查清单**：AI生成代码后，人工按清单审查
- **重构节奏**：每3个需求完成后，专门做一轮重构

### 3.9 ❌ 调试循环的低效

**问题**：AI调试有时陷入循环——修A→B坏→修B→A又坏→修A→C坏……

**实际案例**：
- Docker容器化6个坑，修了3轮才全部解决
- 历史对话bug涉及8个子问题，修一个暴露下一个
- drizzle HNSW索引，尝试了3种API写法才找到运行时不崩溃的方案

**改进方案**：
- **根因分析优先**：修bug前先花5分钟分析根因，而非直接改代码
- **最小验证**：每次修改后立即验证，不要攒一堆改了一起测
- **回滚策略**：连续2次修复失败→git回滚→重新分析→重写

### 3.10 ❌ 知识传递依赖文档

**问题**：Vibe Coding的最大悖论——AI生成代码的效率极高，但确保AI理解项目上下文的成本也很高。

**量化**：
- CLAUDE.md：约200行，每次会话必读
- 3类文档：27+文件，AI需要按需检索
- ADR：11份，架构决策必查
- 踩坑记录：8份，防重复犯错必查

**对比传统开发**：人类开发者靠"项目经验"和"代码熟悉度"，Vibe Coding靠"文档完整度"。文档不完整=AI理解不完整=代码质量下降。

**改进方案**：
- **文档分级**：CLAUDE.md（必读）→ README（概览）→ 详细文档（按需）
- **自动文档生成**：从代码/测试/ADR自动生成文档索引
- **文档健康度检查**：定期检查文档是否与代码同步

## 四、Vibe Coding 效率模型

### 4.1 效率曲线

```
效率
 ↑
 │  ╱╲  从0到1：极高效率
 │ ╱  ╲
 │╱    ╲
 │      ╲  精细调优：效率递减
 │       ╲________________
 │                        ╲  文档维护成本
 │                         ╲____________
 └────────────────────────────────────→ 时间
   原型   功能   评估   调优   维护
```

**关键洞察**：
1. **从0到1**：Vibe Coding效率是传统开发的5-10倍
2. **从1到N**：效率递减，但仍优于传统开发
3. **维护阶段**：文档维护成本是隐藏的效率杀手

### 4.2 成本模型

| 成本项 | 传统开发 | Vibe Coding | 差异 |
|--------|---------|-------------|------|
| 代码编写 | 高（手写） | 低（AI生成） | -80% |
| 代码审查 | 低（自己写的） | 高（AI生成的需仔细审） | +50% |
| 调试 | 中 | 高（AI幻觉+运行时不一致） | +40% |
| 文档维护 | 低（靠记忆） | 高（靠文档） | +100% |
| 评估迭代 | 慢（手改） | 快（AI改） | -60% |
| **综合** | **基准** | **约-30%~+20%** | **取决于阶段** |

### 4.3 最佳实践总结

| 阶段 | 最佳实践 | 原因 |
|------|---------|------|
| 原型 | 大胆让AI生成，快速验证 | 效率最高，沉没成本最低 |
| 功能开发 | SDD约束+AI执行 | 防止AI自由发挥偏离需求 |
| 调优 | 评估驱动+AI迭代 | AI擅长微调参数和prompt |
| 调试 | 根因分析+最小验证 | 避免AI陷入循环修复 |
| 维护 | 文档驱动+定期审计 | 确保AI理解与代码同步 |

## 五、面试话术

### Q: 你怎么看待Vibe Coding？

> Vibe Coding在从0到1阶段效率极高——我这个项目75天完成了传统开发半年以上的工作量。但它有三个隐藏成本：第一，代码审查成本——AI生成的代码看起来合理但可能包含逻辑错误，比如我遇到的drizzle HNSW索引问题，tsc通过但运行时崩溃；第二，文档维护成本——AI没有持久记忆，必须靠文档传递上下文，我建立了CLAUDE.md机制和三类文档体系来解决这个问题；第三，调试循环成本——AI有时会陷入修A坏B的循环，我的应对是"根因分析优先+连续2次失败就回滚重写"。

### Q: Vibe Coding最大的坑是什么？

> AI幻觉的隐蔽性。AI编造的数据看起来完全合理——我的Agent在工具返回fetch failed时，编造了完整的股票数据，包括价格、涨跌幅、成交量，格式和真实数据一模一样。这让我意识到Vibe Coding必须有"不信任AI输出"的意识，关键路径必须增加断言和校验。我后来加了"数据真实性原则"——如果工具调用失败，Agent必须明确告知用户数据不可用，绝不能编造。

### Q: 你怎么解决AI上下文丢失的问题？

> 三层防线：第一层，CLAUDE.md作为开机自检清单，AI每次新会话自动读取，5分钟恢复全局认知；第二层，踩坑记录只追加不修改，确保AI不会重复犯错；第三层，ADR决策记录，确保不同会话的AI做出一致的架构决策。核心原则是"关键信息立即写入文档，不等会话结束"。

## 六、Vibe Coding 成熟度自评

| 维度 | 1分(入门) | 3分(熟练) | 5分(精通) | 自评 |
|------|----------|----------|----------|------|
| Prompt工程 | 简单指令 | 结构化prompt | 模板库+版本管理 | 3 |
| 代码审查 | 不审查 | 抽查 | 系统化审查清单 | 3 |
| 文档管理 | 无 | 有文档 | 自动机读+分级 | 4 |
| 测试策略 | 无 | 单元测试 | 多层测试+属性测试 | 3 |
| 调试效率 | 循环修复 | 根因分析 | 自动化根因定位 | 3 |
| 架构一致性 | 自由发挥 | ADR记录 | 架构门禁+审计 | 3 |
| 成本意识 | 不追踪 | 事后统计 | 实时追踪+优化 | 1 |
| 知识传递 | 靠记忆 | 靠文档 | 自动文档生成 | 3 |

**综合成熟度：2.9/5（熟练水平）**

**最大短板**：成本意识（1分）——没有Token追踪，无法量化Vibe Coding的投入产出比。

**最大优势**：文档管理（4分）——CLAUDE.md+三类目录+ADR+踩坑记录，形成了完整的AI记忆体系。
