# 企微/钉钉/飞书——个人账号审批+机器人限制调研报告

> 调研日期：2026-08-13
> 调研背景：用户没有企业营业执照，只有个人身份注册的账号
> 信息来源：各平台官方文档 + 开放平台API文档 + 社区反馈

---

## 一、钉钉（DingTalk）

### 1.1 审批功能

| 问题 | 结论 | 信息来源 |
|------|------|----------|
| 个人账号能否创建审批流程？ | **不能**。审批是组织级功能，必须在"组织/团队"内使用 | 官方文档：审批API属于"组织应用"范畴 |
| 是否必须创建企业/团队？ | **是**。必须先创建组织（团队或企业） | 官方文档：open.dingtalk.com |
| 个人团队（非认证企业）能否使用审批？ | **能**。钉钉的"团队"不需要营业执照即可创建，团队内可使用审批功能（含OA审批） | 实际测试 + 社区反馈 |
| 未认证企业的审批API限制？ | 基础审批API可用（创建模板、提交审批、获取审批详情），但部分高级功能受限（如审批数据导出、审批流程引擎高级配置） | 官方API文档 |
| 个人开发者能否调用审批API？ | **能**，但需在开放平台创建应用并获取组织授权。个人开发者可注册钉钉开放平台账号，创建应用后获取team_id/org_id | 官方文档：open.dingtalk.com/document/isvapp |

**关键发现**：钉钉对个人最友好——创建"团队"不需要营业执照，只需手机号注册即可。团队内可以正常使用审批功能。

### 1.2 机器人功能

| 类型 | 是否需要企业认证 | 说明 | 信息来源 |
|------|-----------------|------|----------|
| **群机器人（自定义Webhook）** | **不需要** | 任何群成员都可在群设置中添加"自定义机器人"，获取Webhook URL，通过HTTP POST发送消息 | 官方文档：自定义机器人接入群聊 |
| **应用机器人（企业内部应用）** | **不需要企业认证，但需要组织** | 在开放平台创建企业内部应用，启用机器人功能。需要组织（团队即可，无需认证企业） | 官方文档：创建应用 |
| **ISV第三方应用机器人** | **需要企业认证** | ISV上架应用市场需要企业资质 | 官方文档 |

**群机器人 vs 应用机器人区别**：
- 群机器人：仅能往群里推送消息（单向），不支持接收消息、不支持交互式卡片
- 应用机器人：支持接收/回复消息、支持交互式卡片、支持单聊，功能完整

**频率限制**：
- 群机器人：20条/分钟
- 应用机器人：无此限制（受组织级限流控制）

### 1.3 注册门槛

| 项目 | 要求 |
|------|------|
| 创建"团队"（非企业） | 手机号注册即可，**无需营业执照** |
| 创建"认证企业" | 需要营业执照 |
| 免费版 vs 专业版 | 免费版：审批、打卡、日志等基础OA功能可用；专业版（9800元/年）：高级审批流程、数据导出、更多API额度 |

## 二、企业微信（WeCom）

### 2.1 审批功能

| 问题 | 结论 | 信息来源 |
|------|------|----------|
| 个人微信账号能否使用企业微信审批？ | **不能**。企业微信是独立于个人微信的办公平台，必须注册企业微信 | 官方文档 |
| 未认证企业微信能否使用审批API？ | **能**。未认证企业可使用基础审批API（获取模板、提交申请、获取详情），但创建/更新审批模板API需要认证 | 官方文档：developer.work.weixin.qq.com |
| 企业微信注册门槛 | **需要组织主体信息**。注册时需填写组织名称、管理员姓名、手机号。未认证状态下可使用大部分功能 | 官方文档 |

**关键限制**：
- 企业微信注册**不强制要求营业执照**，可以选择"团队/组织"类型注册
- 但未认证企业在**客户联系、会话存档**等高级功能上受限
- 审批API中，`创建审批模板`和`更新审批模板`需要已认证企业

### 2.2 机器人功能

| 类型 | 是否需要企业认证 | 说明 | 信息来源 |
|------|-----------------|------|----------|
| **群机器人（Webhook消息推送）** | **不需要** | 群内任何成员可添加"消息推送"（原群机器人），获取Webhook URL | 官方文档：消息推送配置说明 |
| **智能机器人（应用机器人）** | **不需要认证，但需要企业微信组织** | 在管理后台创建自建应用，启用机器人功能。未认证企业也可创建 | 官方文档：智能机器人概述 |
| **API模式机器人** | **不需要认证** | 支持长连接/WebSocket接收消息，主动回复 | 官方文档 |

**Webhook机器人 vs 智能机器人区别**：
- Webhook机器人（消息推送）：仅能往群内推送消息，单向，支持text/markdown/图片/文件/模板卡片
- 智能机器人：支持接收消息、被动回复、主动回复、交互式卡片，功能完整

**频率限制**：
- Webhook机器人：20条/分钟
- 智能机器人：应用消息受组织级限流

### 2.3 注册门槛

| 项目 | 要求 |
|------|------|
| 注册企业微信 | 需填写组织名称+管理员信息，**不强制营业执照** |
| 未认证企业限制 | 通讯录上限200人、无法使用客户联系高级功能、部分API受限 |
| 认证企业 | 需营业执照，通讯录无上限，全功能开放 |

## 三、飞书（Feishu/Lark）

### 3.1 审批功能

| 问题 | 结论 | 信息来源 |
|------|------|----------|
| 个人飞书账号能否使用审批？ | **不能直接使用**。审批是组织级功能，需在组织内使用 | 官方文档：open.feishu.cn |
| 未认证飞书组织能否使用审批API？ | **能**。飞书审批API对未认证组织开放，包括创建审批定义、提交审批实例等 | 官方文档：审批概述 |
| 飞书注册门槛 | **低**。手机号注册即可创建组织，无需营业执照 | 官方文档 |

**关键发现**：飞书对个人开发者最开放——
- 创建组织无需营业执照
- 审批API完整开放（含创建/更新审批定义）
- 免费版功能非常完整

### 3.2 机器人功能

| 类型 | 是否需要企业认证 | 说明 | 信息来源 |
|------|-----------------|------|----------|
| **群机器人（自定义Webhook）** | **不需要** | 群内添加自定义机器人，获取Webhook URL | 官方文档：自定义机器人 |
| **应用机器人** | **不需要认证，但需要组织** | 在开放平台创建应用，启用机器人能力 | 官方文档：机器人概述 |
| **商店应用机器人** | **需要企业认证** | 上架应用商店需要企业资质 | 官方文档 |

**群机器人 vs 应用机器人区别**：
- 群机器人：仅推送消息，支持富文本/图片/分享群/交互卡片
- 应用机器人：支持接收消息、主动发消息、交互卡片、单聊、群聊，功能最完整

**飞书特色**：
- 群机器人支持**交互式卡片**（按钮回调），比钉钉/企微的群机器人功能更强
- 应用机器人支持**长连接**接收消息，无需公网服务器

### 3.3 注册门槛

| 项目 | 要求 |
|------|------|
| 创建组织 | 手机号注册即可，**无需营业执照** |
| 免费版限制 | 最多50人（可申请扩容）、基础功能全开放、API无额外限制 |
| 商业版/旗舰版 | 付费，更多管理功能、更大存储、更高级安全 |

## 四、微信（个人微信 + 公众号/小程序）

### 4.1 个人微信机器人

| 方案 | 现状 | 风险 | 信息来源 |
|------|------|------|----------|
| **itchat/gechat等协议库** | **已失效/高风险** | 微信官方严厉打击非官方客户端登录，封号风险极高 | 社区反馈（2023年后大量封号） |
| **WeChatFerry (wcferry)** | 仍在维护，但风险同上 | 基于逆向Hook，随时可能因微信更新失效，封号风险高 | GitHub社区 |
| **ComWeChatRobot** | 已停更 | 同上 | GitHub |

**结论**：个人微信机器人方案**不推荐**，封号风险极高，且违反微信用户协议。

### 4.2 微信公众号机器人

| 类型 | 注册门槛 | 机器人能力 | 信息来源 |
|------|----------|-----------|----------|
| **个人订阅号** | 个人身份证即可注册 | 有限：被动回复消息（用户发消息后48h内可回复1次）、不支持客服消息、不支持网页授权 | 官方文档 |
| **企业订阅号** | 需组织/企业信息 | 同个人订阅号，但可认证 | 官方文档 |
| **服务号** | **需企业/组织资质** | 完整：客服消息、模板消息、网页授权、微信支付等 | 官方文档 |

**关键限制**：
- 个人订阅号**不能做真正的机器人**——只能被动回复，不能主动推送
- 服务号需要企业资质（营业执照或组织机构代码）
- 个人订阅号**每天1次群发**，接口调用次数受限

### 4.3 微信小程序

| 项目 | 说明 | 信息来源 |
|------|------|----------|
| 个人小程序 | 个人身份证可注册，但服务类目受限 | 官方文档：mp.weixin.qq.com |
| 机器人能力 | 小程序本身不是机器人，但可通过"客服消息"实现类似功能 | 官方文档 |
| 限制 | 个人小程序不支持微信支付、不支持直播、服务类目有限 | 官方文档 |

## 六、推荐方案

### 6.1 现在就能做的（无需营业执照）

| 优先级 | 方案 | 平台 | 实现方式 |
|--------|------|------|----------|
| **P0** | 群消息推送机器人 | 钉钉/企微/飞书均可 | Webhook机器人，HTTP POST即可，5分钟搞定 |
| **P1** | 审批流程 | **飞书**（首选）或**钉钉** | 创建免费组织→配置审批模板→调用API |
| **P1** | 应用机器人（可交互） | **飞书**（首选）或**钉钉** | 创建免费组织→开放平台创建应用→启用机器人 |
| **P2** | 微信个人订阅号 | 微信 | 个人身份证注册，被动回复消息 |

### 6.2 需要预留接口，等有企业账号后快速接入

| 功能 | 当前替代方案 | 未来正式方案 | 需要的资质 |
|------|-------------|-------------|-----------|
| 微信服务号机器人 | 飞书/钉钉应用机器人 | 微信服务号（客服消息+模板消息） | 营业执照 |
| 企微审批模板创建 | 飞书审批API（全功能） | 企微审批API（创建/更新模板） | 企业认证 |
| 微信支付 | 暂不实现 | 微信支付API | 营业执照+商户号 |
| 客户联系（企微） | 暂不实现 | 企微客户联系API | 企业认证 |

### 6.3 替代方案：开源OA替代SaaS审批

| 开源OA | 审批能力 | 部署方式 | 适合场景 |
|--------|---------|---------|---------|
| **Dify** | 工作流编排（非传统审批） | Docker自部署 | AI Agent工作流 |
| **n8n** | 自动化工作流 | Docker自部署 | 审批流+自动化 |
| **Outline** | 知识管理+简单审批 | Docker自部署 | 轻量审批 |
| **直接自建** | 自定义审批引擎 | 已有FastAPI后端 | 完全定制 |

**推荐路径**：
1. **短期**（现在）：飞书免费组织 → 审批+机器人全功能可用
2. **中期**（有企业资质后）：企业微信/微信服务号 → 覆盖微信生态
3. **长期**：自建审批引擎 → 完全自主可控，不依赖第三方

### 6.4 架构建议：抽象层设计

```
┌─────────────────────────────────┐
│        AI Agent Platform        │
├─────────────────────────────────┤
│    NotificationAdapter (抽象)    │
│  ┌───────┬───────┬───────┐      │
│  │DingTalk│WeCom  │Feishu │      │
│  │Adapter │Adapter│Adapter│      │
│  └───────┴───────┴───────┘      │
├─────────────────────────────────┤
│    ApprovalAdapter (抽象)        │
│  ┌───────┬───────┬───────┐      │
│  │DingTalk│WeCom  │Feishu │      │
│  │Approval│Approval│Approval│    │
│  └───────┴───────┴───────┘      │
├─────────────────────────────────┤
│    BotAdapter (抽象)             │
│  ┌───────┬───────┬───────┐      │
│  │DingTalk│WeCom  │Feishu │      │
│  │Bot     │Bot    │Bot    │      │
│  └───────┴───────┴───────┘      │
└─────────────────────────────────┘
```

**核心原则**：
- 通知/审批/机器人功能均通过Adapter抽象
- 先实现飞书Adapter（门槛最低、功能最全）
- 后续添加企微/钉钉/微信Adapter只需实现接口
- 配置切换：`config/api_keys.yaml` 中配置启用的平台

## 八、总结

### 一句话结论

**飞书是个人开发者（无营业执照）的最佳选择**——免费组织即可使用审批全功能+机器人全功能，API限制最少。

### 行动路线

1. **立即**：注册飞书免费组织 → 创建应用机器人 → 配置审批模板
2. **同步**：钉钉创建团队 → 群Webhook机器人（消息推送）
3. **预留**：代码中抽象NotificationAdapter/ApprovalAdapter/BotAdapter接口
4. **未来**：有企业资质后 → 企微+微信服务号 → 覆盖微信生态用户
