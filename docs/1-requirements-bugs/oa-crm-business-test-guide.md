# OA/CRM 业务测试指南——面向业务任务

> **版本**：v1.0 | **日期**：2026-08-13
> **定位**：面向业务人员的端到端测试指南，不是单元测试，不是技术测试
> **系统范围**：Odoo Community（OA）+ Twenty CRM（CRM）+ AI Agent（自然语言操作）
> **测试原则**：从用户发起操作到最终业务结果的全链路验证

---

## 一、测试概述

### 1.1 测试目标

验证 AI Agent 能否通过自然语言，端到端完成企业 OA/CRM 的真实业务流程，确保：

- 用户说一句话，Agent 能正确理解意图并执行操作
- OA/CRM 系统状态正确变更
- 审批/通知/联动等跨角色流程完整闭环
- 异常场景有友好提示，无数据泄露

## 二、OA 业务测试场景

### 场景 OA-01：请假审批

**业务背景**：某科技公司员工李明因家中有事需要请假2天，需通过审批流程获得经理和HR的批准。

**用户故事**：As a 普通员工，I want to 通过Agent提交请假申请，so that 我不需要登录OA系统就能完成请假流程。

**操作步骤**：

| 步骤 | 角色 | 操作 | Agent 行为 |
|------|------|------|-----------|
| 1 | 李明 | 对Agent说："帮我请后天和后后天两天的年假，原因是家里有事" | Agent 解析：请假类型=年假，开始日期=后天，结束日期=后天+1，原因=家里有事 |
| 2 | Agent | 调用 Odoo `hr.leave` 创建请假申请 | 返回："已为您提交年假申请（8月15日-8月16日），审批单号：LEAVE-2026-0042，已通知您的经理王芳审批" |
| 3 | 王芳 | 对Agent说："审批李明的请假申请" | Agent 列出待审批项，王芳确认同意 |
| 4 | Agent | 调用 Odoo `approval.request` 执行审批 | 返回："已批准李明的年假申请（8月15日-8月16日），已转HR确认" |
| 5 | 张静 | 对Agent说："确认李明的请假" | Agent 执行HR确认 |
| 6 | Agent | 更新请假状态为"已确认"，扣除年假余额 | 返回："李明的年假已确认，年假余额剩余3天" |

**预期结果**：
- Odoo 中 `hr.leave` 记录状态为"已确认"（validate）
- 李明的年假余额减少2天
- 李明收到请假审批通过的通知

**验收标准**：
- [ ] 李明说一句话即可发起请假，无需手动填写表单
- [ ] 审批链路完整：经理审批→HR确认
- [ ] 年假余额正确扣减
- [ ] 请假记录可在Odoo日历视图中显示

### 场景 OA-02：报销流程

**业务背景**：销售部陈浩出差拜访客户，产生差旅费¥3,500，需要提交报销申请。

**用户故事**：As a 销售人员，I want to 通过Agent提交差旅报销，so that 我在出差途中就能完成报销，不用回公司再处理。

**操作步骤**：

| 步骤 | 角色 | 操作 | Agent 行为 |
|------|------|------|-----------|
| 1 | 陈浩 | 对Agent说："帮我提交一个差旅报销，金额3500元，包含机票1200、酒店1500、餐饮800，出差目的是拜访华为客户" | Agent 解析报销明细 |
| 2 | Agent | 调用 Odoo `hr.expense` 创建报销单，含3条明细 | 返回："已提交差旅报销单 EXP-2026-0018，总金额¥3,500，已通知经理王芳审批" |
| 3 | 王芳 | 对Agent说："审批陈浩的报销单" | Agent 展示报销明细，王芳确认同意 |
| 4 | Agent | 经理审批通过，流转到财务 | 返回："陈浩的报销单已批准，已转财务赵磊确认" |
| 5 | 赵磊 | 对Agent说："确认陈浩的报销，安排打款" | Agent 执行财务确认 |
| 6 | Agent | 更新状态为"已付款"，记录付款日期 | 返回："陈浩的报销¥3,500已确认付款，预计3个工作日到账" |

**预期结果**：
- Odoo 中 `hr.expense` 报销单状态为"已付款"（done）
- 报销明细包含3条：机票、酒店、餐饮
- 陈浩收到付款通知

**验收标准**：
- [ ] Agent 能从一句话中拆解出多条报销明细
- [ ] 审批链路完整：经理→财务
- [ ] 报销金额合计正确
- [ ] 付款状态正确更新

### 场景 OA-03：通知公告

**业务背景**：HR张静需要发布一条系统维护通知，要求全员知晓并确认已读。

**用户故事**：As a HR，I want to 通过Agent发布全员通知，so that 我不需要逐个通知就能确保信息传达到位。

**操作步骤**：

| 步骤 | 角色 | 操作 | Agent 行为 |
|------|------|------|-----------|
| 1 | 张静 | 对Agent说："给全员发一个通知：本周六上午9点-12点系统维护，届时OA和CRM系统暂停服务，请提前保存工作" | Agent 解析通知内容 |
| 2 | Agent | 调用 Odoo `mail.channel` 发布公告 | 返回："已发布全员通知【系统维护通知】，通知ID：NOTICE-2026-0033，已推送给全部28名员工" |
| 3 | 李明 | 对Agent说："我有哪些未读通知？" | Agent 查询未读通知列表 |
| 4 | Agent | 返回未读通知，包含系统维护通知 | 返回："您有2条未读通知：1.系统维护通知（HR张静发布）2.周五团建活动通知" |
| 5 | 李明 | 对Agent说："标记已读" | Agent 更新已读状态 |
| 6 | 张静 | 对Agent说："系统维护通知的已读情况如何？" | Agent 统计已读/未读人数 |

**预期结果**：
- Odoo 中公告已创建，所有员工可在 Discuss 频道看到
- 已读/未读状态可追踪
- 张静可查看已读统计

**验收标准**：
- [ ] 一句话即可发布全员通知
- [ ] 所有员工能收到通知推送
- [ ] 已读/未读状态可查询
- [ ] HR可查看已读统计人数

### 7.3 缺陷分级

| 级别 | 定义 | 示例 | 处理时限 |
|------|------|------|---------|
| **P0-阻塞** | 核心流程完全不通 | Agent无法创建请假申请 | 立即修复 |
| **P1-严重** | 核心流程部分不通或数据错误 | 审批通过但余额未扣减 | 24小时内 |
| **P2-一般** | 非核心功能异常或体验不佳 | 追问顺序不合理 | 本迭代内 |
| **P3-建议** | 体验优化建议 | 提示语不够友好 | 下个迭代 |
