# ADR-004: RAG 混合检索 + 分离精排策略

## 状态：已采纳（2026-05）

## 背景

项目初始仅使用稠密检索（pgvector 余弦相似度），在金融文档检索场景下暴露两个核心问题：

1. **召回率不足**：单一向量检索对关键词精确匹配（如股票代码、财务指标名称）效果差
2. **精排质量下降**：图谱三元组（短文本，50-100 字）和文档 chunk（长文本，500-800 字）混合精排时，短文本因语义集中获得更高分数，挤掉高质量长文本 chunk

## 决策

采用混合检索（稠密 + 稀疏 + RRF 融合）+ 分离精排（文档 Top-5 + 图谱 Top-3）策略。

## 理由

1. **BM25 补充关键词匹配**：nodejieba 中文分词 + BM25 算法，精确匹配股票代码、财务术语
2. **RRF 融合互补**：Reciprocal Rank Fusion (K=60) 融合稠密和稀疏检索结果，兼顾语义相似和关键词匹配
3. **分离精排**：文档 chunk 和图谱三元组分别精排，避免短文本挤占长文本位置
4. **图谱限流**：精排前按分数降序取 Top-5，防止噪声三元组影响排序质量

## 后果

### 正面
- Top-5 准确率提升 40%+
- 关键词精确匹配场景（股票代码、指标名称）召回率显著提升
- 精排结果更均衡，文档和图谱各有合理占比

### 负面
- 检索链路变长（双路检索 + RRF + 分离精排），延迟增加约 200ms
- BM25 分词质量依赖 nodejieba，金融专业术语需同义词扩展补充
- Reranker 服务成为单点故障（已通过降级到原始排序缓解）

### 风险缓解
- Reranker 失败时降级到 RRF 原始排序
- 金融同义词扩展（QueryExpander）补充 BM25 分词不足
- HyDE 查询改写弥补用户 query 与文档表述的词汇鸿沟
