# ADR-009: 数据服务缓存从 SQLite 迁移到 PostgreSQL

## 状态：已采纳（2026-05）

## 背景

Python 数据服务（data_service）使用 SQLite 作为本地缓存，在多实例部署和跨服务访问场景下暴露问题：

1. **文件锁竞争**：SQLite 的文件级锁在高并发写入时性能急剧下降
2. **数据不一致**：多个数据服务实例各自维护 SQLite 文件，缓存数据不同步
3. **运维复杂**：SQLite 文件需要挂载卷持久化，Docker 部署时增加配置复杂度

## 决策

将数据服务缓存从 SQLite 迁移到 PostgreSQL（PgCache 类）。

## 理由

1. **统一数据存储**：项目已有 PostgreSQL 实例，无需引入新组件
2. **无文件锁问题**：PostgreSQL 的行级锁支持高并发读写
3. **跨服务共享**：多个数据服务实例共享同一 PostgreSQL 缓存，数据一致
4. **Docker 友好**：无需挂载卷，数据服务无状态化

## 后果

### 正面
- 消除文件锁竞争，缓存写入性能提升
- 多实例缓存数据一致
- 数据服务无状态化，水平扩容更容易

### 负面
- 缓存读取延迟从 <1ms（本地 SQLite）增至约 5ms（网络 PostgreSQL）
- 增加主数据库负载

### 风险缓解
- PgCache 支持设置 `expiresAt` 自动过期，避免缓存无限增长
- 缓存命中率约 80%，实际 PostgreSQL 额外负载可控
